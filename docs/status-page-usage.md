# 状态页用量口径设计(status-page-usage)

状态页(`/memory/status`)的用量图表曾混排两种统计范围,导致「重启后消耗归零」「小图与每日图对不上」。本文记录调查结论、用户故事与统一口径的决策。

## 背景与问题(调查结论)

状态页六块用量的数据源与范围如下(修复前):

| 图表 | 数据源 | 范围 | 重启后 |
|---|---|---|---|
| Token 分布(按职责) | `runtime.usage`(内存) | 本进程 | **归零** |
| LLM 调用消耗(输入/输出/缓存读) | `runtime.usage`(内存) | 本进程 | **归零** |
| 用量明细表 | `runtime.usage`(内存) | 本进程 | **归零** |
| 静态上下文成本估算 | `runtime.state.teams` + 摘要 | 本进程实时 | 视 warmup |
| 近 14 天每日用量 | `usage.jsonl`(持久化) | host 级 | 保留 |
| 近 12 周日历热力图 | `usage.jsonl`(持久化) | host 级 | 保留 |

根因:**一页混排「本进程内存态」与「host 级持久态」两种范围,且无任何范围标注**。三个症状由此而来:① 重启后消耗类图表归零(内存态),与每日图的历史值(持久态)矛盾;② 「静态上下文成本」(上下文估算)与「每日用量」(实际消耗)是两种不同的度量,并排展示无说明,自然「对不上」;③ 跨进程并跑时,每个面板只看到自己进程的消耗,与目录页/节点页已确立的 host 级心智不一致。

## 用户故事

1. 作为用户,重启 dsh web 后,我希望状态页的消耗图表仍显示历史消耗,不因进程重启归零——消耗是 host 级持久事实,不是进程内临时状态。
2. 作为用户,我想一眼分清每张图表的统计范围:哪些是「近 14 天 host 级持久消耗」,哪些是「本进程实时装载」,不再被混排误导。
3. 作为用户,「Token 分布」「LLM 调用消耗」「近 14 天每日用量」应可对账:甜甜圈合计 = 每日用量各柱合计(同一时间窗、同一数据源);今日柱包含当前进程刚发生的调用。
4. 作为用户,多个 dsh 会话并跑时,消耗类图表应聚合 host 上全部进程的消耗(usage.jsonl 是各进程共享追加的),而不是只显示打开面板的这个进程。

## 决策

- **消耗类图表(Token 分布 / LLM 调用消耗 / 用量明细)统一读 `usage.jsonl`,按「近 14 天」聚合**——与「近 14 天每日用量」同窗、同源,甜甜圈合计恒等于每日柱合计(同一聚合派生的两个视图)。
- **每日用量 / 热力图不变**:usage.jsonl 按 84 天零填充;「近 14 天每日用量」是其中最近 14 天的切片。
- **静态上下文成本保持「本进程实时」**——team 装载与摘要体积是进程内存态(跨进程的装载状态由节点页提供),标题明确标注「本进程」,与消耗类图表分区展示。
- **全部图表标题携带范围**:消耗类带「近 14 天」,上下文成本带「本进程」;图表区加一行范围说明。
- **为什么不「全部本进程」**:跨进程并跑时各面板只见自身消耗,且重启归零违背「记忆系统的消耗」心智;**为什么不「全部 host 实时」**:team 装载是内存态,只有状态文件快照(节点页已提供),消耗是事实数据,天然持久。
- `/lmemory usage`(CLI)保持本进程口径不变——命令是会话内的人操作面,「this process」标注已有;面板是 host 级观测面。

## 机制

- `src/usage-log.ts` 新增 `aggregateWindowTotals(rows, days)`:复用 `aggregateByDay` 的同窗过滤,按职责累计 calls/input/output/cacheRead(零填充日求和 = 真实行求和),保证与每日图**数学恒等**。
- `dashboard()`(index.ts)一次 `readUsageRows()`,派生 `totals`(近 14 天)与 `daily`(84 天);`runtime.usage` 退出面板数据源,只服务 `/lmemory usage`(CLI)与节点页的 calls 快照。
- DTO:`DashboardDto.usage.counters` → `usage.totals`(同形:label/calls/inputTokens/outputTokens/cacheReadTokens);面板 api.ts 镜像同步。

## 验收标准(AC)

- **重启保留**:进程重启后,Token 分布 / LLM 调用消耗 / 用量明细显示历史值(>0),与重启前一致。
- **对账恒等**:甜甜圈中心合计 = 近 14 天每日用量各柱合计(同一 `aggregateByDay(14)` 派生,单测锁定恒等);今日柱包含当前进程新调用。
- **范围标注**:消耗类图表标题含「近 14 天」;静态上下文成本标题含「本进程」;图表区有范围说明行。
- **空态**:近 14 天无任何 usage 行时,消耗类图表显示占位文案(此前「本进程尚无 LLM 调用」改为「近 14 天尚无 LLM 调用」)。
- **契约与视觉**:`aggregateWindowTotals` 单测;web-ui 契约测试 fixtures 更新为 totals;xbrowser 三引擎通过(零 console 错误)。

## 非目标

- 不改 `/lmemory usage`(CLI 会话口径,已有 this process 标注)。
- 不改节点页(calls 快照仍取自本进程 usage 计数,其语义是「该进程的节点活动」)。
- 不做跨主机聚合(usage.jsonl 本就按 host 存放)。
